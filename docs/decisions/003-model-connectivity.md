# 003: Explicit provider wire format and honest replay

Date: November 7, 2026. Status: typed adapters/replay/error paths passed; both live integrations blocked.

Commands: `pnpm probe:models`, `HARNESS_CLOUD_ENABLED=1 pnpm probe:models --live` (exit 2 with missing configuration), `pnpm test`. Evidence: `evidence/models-replay.json`, `evidence/models-live.json`, `evidence/unit-tests.log`. All image evidence is generated synthetic content. No provider credentials were available, and no provider network request was made by the blocked live run.

Llama has an explicit `openai-chat` schema adapter for a configured HTTPS endpoint and declared vision-capable Meta Llama model. The smoke request asks for image text/color with JSON-schema output; runtime validation and the independently known image content must both pass. No endpoint, hosting vendor, or alternative model is silently selected. Required configuration: `LLAMA_SCHEMA=openai-chat`, `LLAMA_ENDPOINT`, `LLAMA_MODEL`, `LLAMA_API_KEY`, plus `HARNESS_CLOUD_ENABLED=1`. A model identifier containing Llama is a configuration guard, not cryptographic proof of provider model identity. Provider deployment, image support, structured-output support, exact returned revision and retention still need live validation.

Snap implements the documented `POST https://api.subq.ai/v1/systemone`, model `subq-snap-1.1`, Bearer authentication, state/images/named questions, with actual noul, choice probabilities/confidence and score legend/probabilities fields. It validates required question names/types, choice domain, normalized probability distributions and score consistency. Snap image limits: 4 images, 4 MiB each/8 MiB total decoded, 13 MiB body. The spike requires its one synthetic image; missing evidence is an error/inconclusive. The HTTP transport limits responses, disallows redirects and applies a deadline. Required live prerequisite: `SUBQ_API_KEY` and enabled cloud processing.

Responses are labeled live versus replay, and replay provenance is explicitly **hand-authored-synthetic**, not recorded provider output. HTTP failures, network/timeout errors and malformed output are tested with transport mocks. No outage or invalid output falls back to replay. These passing tests establish adapter behavior only. Live missing prerequisites are recorded as inconclusive, never passed. Probe thresholds are uncalibrated capability thresholds and cannot authorize promotion.

Decision: keep provider request/response parsing inside typed adapters with configurable wire format for Llama and dedicated Snap schema. Keep deterministic CSV failures authoritative. Metadata records hashes, versions, usage, latency and hashed request IDs without logging provider error bodies, credentials, headers or endpoint URLs. One bounded call/provider with no retries limits this probe; account spend/retention settings and provider pricing are unresolved prerequisites before real user evidence.

Primary references checked November 7, 2026: [Snap Decisions API](https://docs.subq.ai/endpoints/decisions-api/), [authentication](https://docs.subq.ai/using-the-api/authentication/), [retention](https://docs.subq.ai/using-the-api/data-retention/), [Meta Llama 4 model card](https://github.com/meta-llama/llama-models/blob/main/models/llama4/MODEL_CARD.md). No hosted Llama provider contract has been verified because no deployment has been configured.
