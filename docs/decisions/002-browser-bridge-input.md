# 002: Real native messaging and extension CDP input

Date: November 7, 2026. Status: live Chrome for Testing bridge/input proven; installed consumer Chrome and restart coverage remain open.

Commands: `pnpm test`, `pnpm probe:browser`, `pnpm probe:browser --headed`. Evidence: `evidence/browser-headless.json`, `evidence/browser-headed.json`, `evidence/unit-tests.log`. The extension is raw MV3 JavaScript for the spike; WXT/React scaffolding belongs to Phase 1. Browser versions are recorded separately from installed consumer Chrome.

The complete live path is extension `connectNative` → Chrome-spawned Node host → authenticated user-only Unix socket → coordinator → acknowledgment. Fragmented/coalesced native frames, invalid lengths, duplicate ping delivery, initially absent coordinator, and coordinator restart are exercised. Messages are capped at 64 KiB, below Chrome's native-host outgoing limit. Screenshots stay in the extension/test evidence path and never traverse native messaging. A token and owner-only permissions restrict local socket access. There is no network listener for the coordinator. This does not establish same-user attacker resistance or kernel peer-credential attestation.

An initial host-registration attempt timed out. Chromium source confirms `DIR_USER_NATIVE_MESSAGING` is relative to `DIR_USER_DATA`: a custom profile must register under that profile's `NativeMessagingHosts`. Tests now do this entirely in temporary profiles. A second attempt found/launched the host but stalled with the host modules located in the Documents development tree. Installing self-contained modules alongside the temporary launcher resolved it. The precise reason for the stall was not established (macOS protected-folder access is a possibility, not a finding). No OS permissions were changed. The manual installer similarly uses an ordinary Application Support installation.

The extension assigns a new tab, attaches debugger for this execution, and uses Page screenshot/layout/frame methods and Input mouse/text methods. Input is restricted to the assigned tab/window and exact fixture URL; bounded arguments, loader/viewport identity, 10-second expiration and single-use observations guard the spike. Navigation detaches. Tests read the input value only to assert the result; they do not click/type through DOM scripts or call fixture APIs in place of CDP input.

All eight DPR/zoom/active-tab combinations passed in each headed and headless run. The test records active-tab and window-focused flags rather than assuming them. Screenshot pixel widths vary with browser zoom and DPR; see actual measured ratios in the JSON. Coordinates supplied to Input are CSS viewport pixels. Decision: carry measured screenshot-to-CSS mapping in observations and invalidate on zoom/viewport/navigation changes. Do not use native window pixel coordinates directly. These results do not prove behavior while another macOS app is focused, the screen is locked, the browser is minimized, or a dialog intercepts input.

Open: manual installed Chrome 156.0.8078.80 smoke test; MV3 suspension/reload; browser restart; debugger takeover by DevTools; durable sequence recovery; socket peer credentials; cross-document/action budgets and cancellation during input. Ping deduplication is bounded and in memory, and resets with the coordinator. It is not authorization to replay side-effecting actions. The coordinator is a companion stand-in, not Electron or a mocked native API.
